# 更新日誌

本文件記錄 IP檢測 的主要版本更新。

## 未發布 - 2026-11-13

### 改以「網路診斷雷達」為主體

- 主頁、小工具與資料結構改用網路診斷雷達（ByteValley/NetTool）的架構：主頁列出出口、連線、Surge 狀態、串流、AI 與設定；小工具改為雷達的小／中／大型卡片，大型為兩欄卡片＋服務網格＋底部指標。
- 原本 IPCheck 的檢測頁改為輔助的「IP 詳細檢測」，從主頁「出口」區開啟，保留多來源位置對照、proxycheck／IPPure 風險評分、WebRTC 洩漏檢查、地圖與手動查詢 IP。
- 雷達原本只確認可連線的服務檢測，改用 IP-Media 的深度判定：Netflix 分完整片庫／僅自製、YouTube Premium 與 Disney+ 判斷地區、ChatGPT 比對支援地區與 App 限制、動畫瘋限台灣；狀態分可用、部分、將上線、不可用、未知。
- 直式特大等系統未列名的尺寸依實際大小套用大型版面，多出的高度顯示一張「出口詳情」卡。
- 主頁與 IP 詳細檢測共用同一個「遮蔽 IP」設定，首次沿用舊版檢測頁的隱私模式；Surge x-key 首次沿用前一版的設定。
- 恢復 Surge 腳本的 `SYNC` 參數（只送到使用者指定的網址），主頁可填「Surge 快照網址」讓小工具直接顯示 Surge 端依策略檢測的結果。

### 在地化與資料來源

- 全部介面改為繁體中文（台灣用語），台灣以獨立國家顯示並正常顯示 🇹🇼 旗幟；旗幟改用系統 emoji，不再附帶 248 張國旗圖檔。
- 移除雷達原本的中國來源：直連延遲（miui、vivo、百度、QQ）改為台灣延遲（HiNet、中華電信、TWNIC、台大），本地出口查詢（ipip.net、3322.net）移除；DeepSeek、TikTok 換成 Copilot、動畫瘋；中國電信業者對照與「中國大陸」預設歸屬移除。
- 策略群組名稱（例如「AI」）不再被誤判成國碼。

### 移除

- 舊的地圖小工具與其共享快照（`utils/widget_sync.ts`）、小工具點擊重新整理的 App Intent；地圖仍保留在 IP 詳細檢測頁。

### 驗證與限制

- 回歸斷言 135 項通過（Node 搭配 Scripting 模組替身）；`index.tsx`、`widget.tsx`、`page.tsx`、`src/ui.tsx` 通過打包檢查。
- 尚未在實機執行：小工具版面、主頁與詳細檢測頁的切換、Surge 快照同步都待裝置上確認。

## 未發布 - 2026-11-12

### 修正小工具在未知尺寸下落入小型版面

- 問題：系統回報的尺寸名稱不在腳本認得的清單內時（例如直式特大尺寸），大尺寸小工具會套用小型版面，只剩四行文字且不載入地圖。
- 修正：尺寸名稱不認得時改依實際顯示大小判定版面（高度 280pt 以上視為大型），地圖也不再限定特定尺寸才載入。
- 驗證：回歸斷言增為 136 項；尚未在實機確認新尺寸下的版面。

### 整合 Surge

- 頁面新增「Surge」區：填入 HTTP API 的 x-key 後顯示出站模式、目前節點、協定與策略群組；x-key 只存在本機 Storage，以 `X-Key` 標頭送往本機 Surge，不寫入 repo。
- 目前節點優先取最近請求中實際承載流量的策略；沒有經節點的請求時，改以 `/v1/policy_groups/select` 查各群組目前的選擇往下解析，查不到就明確顯示讀不到，不猜測。
- 解鎖檢測完成後讀取 `/v1/requests/recent`，在每項服務旁標出實際經過的策略（節點名稱、直連或被規則攔截）。
- 新增 `surge/ipcheck-radar.sgmodule` 與 `surge/ipcheck-radar.js`：以 Surge 的 policy 參數分別檢測代理出口與直連出口，每 30 分鐘推送摘要通知，可用 `POLICY`／`LMT`／`AI` 指定策略。
- Surge 腳本同樣移除中國來源：直連出口改用 ipify → icanhazip → AWS 與 ipwho.is，直連延遲改用台灣端點，DNS 與電信業者對照改為 HiNet、TWNIC Quad101、中華電信、台灣大哥大、遠傳等；未保留原本的 `SYNC` 快照上傳。
- 驗證：回歸斷言增為 134 項（群組解析、節點判定、巢狀群組、服務策略對照、設定正規化、金鑰遮罩）；Surge 腳本以替身環境完整跑過一次，28 個請求中沒有中國網域。HTTP API 的端點與驗證方式已對照 Surge 官方手冊，但尚未連上真實的 Surge 執行。

### 整合網路診斷與解鎖檢測

- 併入「IP-Media 流媒體解鎖檢測」（iam-Kristen/Scripting）與「網路診斷雷達」（ByteValley/NetTool）的檢測邏輯，全部改寫為繁體中文（台灣用語）並沿用本頁的連續面板樣式；只在檢測目前出口時顯示，手動查詢 IP 時隱藏。
- 新增「網路診斷」區：連線類型（Wi-Fi／行動網路）、本機位址（隨隱私模式遮罩）、NAT 推估、IPv6、國際延遲、台灣延遲、HTTP/3（QUIC）。
- 新增「串流解鎖」區：YouTube Premium、Netflix（完整片庫／僅自製）、Disney+、巴哈姆特動畫瘋會判斷地區與可觀看範圍；Spotify、Prime Video 確認可連線。
- 新增「AI 服務」區：ChatGPT 比對支援地區與 App 限制；Claude、Gemini、Copilot、Grok、Perplexity 確認可連線，Cloudflare 站點另以 `/cdn-cgi/trace` 顯示該服務實際看到的出口地區。
- 大型小工具新增一行解鎖摘要（串流 n/6 · AI n/6 · 國際延遲），資料來自頁面最近 24 小時內的檢測，小工具本身不另外發出請求。

### 移除中國來源

- 直連延遲原本使用的 `connect.rom.miui.com`、`wifi.vivo.com.cn`、`www.baidu.com`、`www.qq.com` 全部移除，改為「台灣延遲」：HiNet、中華電信、TWNIC、台灣大學。
- 本地出口查詢 `myip.ipip.net`、`ip.3322.net` 移除；出口位址沿用既有的 ipify → icanhazip → AWS 探針，不另外查詢。
- 服務清單移除 DeepSeek 與 TikTok，改為 Microsoft Copilot 與巴哈姆特動畫瘋；電信業者簡稱對照（中國移動／聯通／電信／廣電、阿里雲、騰訊雲）與「中國大陸」預設歸屬一併移除。
- 未併入原雷達的 Surge 模組、Surge HTTP API 設定與快照同步，也未加入國旗與服務圖示圖檔。

### 驗證與限制

- 回歸斷言由 99 項增為 123 項（trace 解析、NAT 與介面分類、Netflix／YouTube／ChatGPT／動畫瘋判定、連線檢測、摘要解析、探測點不含中國網域），以 Node 搭配 Scripting 模組替身執行通過；三個入口檔通過語法與匯入打包檢查。
- 本次未在實機執行：新區塊的版面、各服務實際回應格式與台灣延遲端點的可用性尚待裝置上確認。動畫瘋檢測沿用公開的 token 介面流程，若該介面調整會顯示「檢測失敗」而非誤判。
- 連線檢測把 HTTP 5xx 以下視為可連線（403 可能只是防機器人驗證），不代表帳號可在當地註冊或付費。

### 小工具與頁面同步

- 頁面每次檢測完成後寫入共享快照（目前 IP、歸屬、經緯度、風險、網路屬性、風險標記）；小工具優先讀取該快照，不再自己另查一份出口 IP，修復地圖與 IP 停留在上一次查詢的問題。
- 小工具風險優先使用 proxycheck，缺失時改用 IPPure；只有從未開啟過頁面、沒有快照時才使用本地啟發式，並明確標註“估算”。0 分不繪製刻度條，與頁面規則一致。
- 檢測完成與隱私切換後統一延遲 300ms 呼叫 `Widget.reloadUserWidgets()`，避開共享儲存後台落盤，避免小工具讀到上一份快照或舊隱私設定。
- 驗證：快照構建、風險優先順序、未標記/未知區分與座標校驗等 92 項迴歸斷言通過；systemMedium 實際預覽顯示 8.8.8.8、Mountain View、風險 42%，確認使用快照而非即時自查。

### 風險標記精簡與動效

- 代理、VPN、Tor、匿名化、爬蟲、受侵害六類標記改為只渲染明確命中項；`false`、`null`、查詢中與暫無資料不再生成“未標記/暫無資料”佔位行，空結果時整區不佔高度。
- 命中標記逐條彈入（透明度、位移、縮放、彈簧），標籤外圈迴圈掃出同色光環；代理沿用 proxycheck 優先、ip-api 備援，仍排在首位。
- 說明文案同步改為“僅列出已命中項，未列出可能是未命中或暫無資料”，避免把空行誤解成安全結論。
- IPPure / Cloudflare / proxycheck 三個風險區為真實 0 分時均不再渲染刻度條，也不再顯示“評分 0 分”文字；0 分視為無風險，不佔位，只有評分缺失時才顯示待取得狀態。
- 驗證：新增標記篩選與零分刻度條迴歸斷言，83 項斷言通過；全專案 TypeScript 診斷通過；命中、未命中與 0 分隱藏刻度條預覽截圖驗證（`tests/preview-flags.tsx`）。

### 腳本審查與維護

- 修復零長度 `::` 壓縮被當作合法 IPv6、帶空白 IPv4 繞過隱私遮罩的問題；WebRTC 與 HTTP 出口共用位址歸一化和公網範圍判斷，補充本地/保留/文件網段過濾及 NAT64 邊界。
- 對 ip-api / ipwho.is 的欄位做執行時收窄，防止異常字串、布林值及缺失欄位導致介面或元件拋錯。缺失座標使用非有限值，不再補零畫錯地圖；真實零經緯度與缺失區分。
- 允許歸屬源失敗時繼續顯示已取得的同位址 proxycheck 信譽資料；位置未知不再丟棄已驗證的 HTTP 出口位址。
- IPPure 網頁風險增加獨立位址校驗；位址缺失或不匹配的分數不採信，官方 API 同址補分不變。WebView 建立納入異常保護，網頁失敗不再連帶丟失官方 API 改用。
- 為小工具地圖等待增加 6 秒應用層預算，失敗/逾時退化為文字資訊；增加頂層異常檢視和頁面入口退出備援。此逾時只停止等待，不是 MapKit 原生任務取消。
- 清理未使用的 `BAND_BG` 匯入、中型小工具不可達的 ISP 分支與冗餘條件、WebRTC 重複位址解析與分類實現；刪除本次一次性網頁探針。
- 驗證：保留 `tests/regression.ts` 離線迴歸入口，76 項斷言通過；全專案 TypeScript 診斷通過；手動 IP 單頁和小號/中號小工具執行驗證通過。本次未重新進行視覺截圖驗收。
- 外部限制：本次 IPPure 網頁實測未獲得成功風險物件，因此 `ipQuality.data.ip` 的成功回應契約仍待樣本確認；缺乏同址證據時保持“未取得”，不借用其他位址的評分。ip-api 免費源仍為 HTTP，未擅自改成不支援的免費 HTTPS；小工具已改為優先讀取頁面共享快照，僅在無快照時使用啟發式估算，見上方“小工具與頁面同步”。

- 參考 NodeQuality / IPQuality 的基礎資訊與風險因子，直接增強現有單頁：按需顯示電信業者、所屬機構、IP 主機名稱，以及大洲、歸屬時區（含 UTC 偏移）、參考郵遞區號；ASN 下方已有的網路名稱自動去重。
- 擴充套件現有 proxycheck v3 回應解析，展示 VPN、Tor、匿名化、爬蟲與受侵害標記；原三態展示已由上方“風險標記精簡與動效”取代，未命中項不再佔位。
- 在原 proxycheck 評分下補充陽性檢測置信度、IP / 網段裝置估算、首次及最近檢出時間；裝置數明確為資料庫估算，記錄時間使用 UTC，不合成新的風險分數。
- 沿用連續面板、統一標籤列和色彩；地圖預設收起及列表互斥邏輯保持不變。新增 IP 主機名稱隨隱私模式隱藏；未增加二級介面或額外網路請求。
- 驗證：21 項解析、零值、IPv6 同址、異常欄位、時區與去重檢查通過；真實介面查詢通過；窄螢幕長文本、風險動畫終點與完整單頁原生截圖驗證通過。此次 8.8.8.8 實測 IPPure / Cloudflare 未回傳同址評分，保留原有缺失狀態。

- 修復 IPv4-mapped IPv6（如 `::ffff:192.0.2.1`）無法輸入查詢、隱私模式可能原樣顯示完整位址的問題；位址比較統一使用規範化結果，壓縮寫法與完整寫法不再被誤判為不同出口。

- 清理未被頁面或小工具消費的 `isNative`、`pinPoint`、`vpnConfidence`、`vpnMethod`、proxycheck 冗餘信譽欄位、位置行國家碼及 IPPure 自身 IP 欄位，刪除一次性網路介面探針 `_probe.ts`。
